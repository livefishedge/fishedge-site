## 3. Source-policy decisions (from bake-off + research)

| Signal | Provider | Freshness class | USEC-MD coverage verdict |
|---|---|---|---|
| Wave H/T/dir (offshore) | Open-Meteo Marine | `MODEL_FORECAST` | 16/16 test points returned data; 6h cycle |
| Wind/gust/pressure/RH/visibility | Open-Meteo Weather | `MODEL_FORECAST` | 16/16 returned; kt + inHg + nm units |
| Observed wind/pressure | NDBC realtime2 | `OBSERVATION` | Live; 10-min cycle; **MM = null, never 0** |
| Observed waves | NDBC realtime2 (44084 only) | `OBSERVATION` | **Sparse** — only ~half of 10-min slots have WVHT/DPD/MWD |
| Tide predictions | NOAA CO-OPS | `DETERMINISTIC` | Inlet-station table covers Ocean City, Indian River, Cape May, Lewes, Chesapeake |
| Marine alerts | NWS `/alerts/active?point=…` | `PUSH_OBSERVATION` | 16/16 reachable; User-Agent required |
| Moon/twilight | Local astronomy | `COMPUTED_LOCAL` | Deterministic, no network |

### Decision on paid/proprietary feeds

**No paid feeds in dev MVP.** The roadmap said evaluate Stormglass / Spire / Sofar-Spotter / PredictWind only after documenting a concrete coverage, latency, or licensing gap. The bake-off showed Open-Meteo + NDBC + CO-OPS + NWS cover all the captain-facing fields the user feedback asked for. Adding a paid dependency now would be premature.

### Decision on NWS CORS in the browser

`api.weather.gov` requires a `User-Agent` header, which the browser `fetch()` cannot send without CORS preflight. The dev MVP only wires the adapter for server-side test execution. **Production deploy must route NWS calls through a Cloudflare Worker proxy.** This is called out as a known gap in §6.

## 5. Captain workflow mapping (per user feedback)

| User-quoted pain | Product response (dev MVP) |
|---|---|
| "Real time accurate weather readings at 4 AM are crucial" | Compact strip shows `Observed N min ago at <station>` for the nearest NDBC; trip window scans all trip hours, not just current |
| "Up to date wave height, interval, dominant swell direction" | Trip timeline table has dedicated columns for Wave / Period / Direction; Open-Meteo Marine fields include swell vs wind-wave split |
| "Integrate tides and moon phases" | CO-OPS tide predictions (next H/L) appear in `now.tide`; moon phase + rise/set computed locally in `now.moon` |
| "All metrics of ocean and weather all in one app" | Single briefing drawer shows decision / now / trip timeline / obs-vs-model per segment; no app-switching |
| "Barometric pressure / humidity" | Open-Meteo Weather provides both; `now.pressure` carries 3h tendency, not the 24h proxy the workspace flagged earlier |
| "Corner the market by replacing multiple subscriptions" | Realistic MVP only — full coverage requires paid feeds we deliberately deferred. Roadmap Phase 3 covers that decision |

## 6. Known gaps (must be closed before any production rollout)

1. **NWS CORS proxy.** Adapter is server-side only today. Browser cannot call `api.weather.gov` directly without a Cloudflare Worker proxy that adds `User-Agent` and forwards the request.
2. **Astronomy adapter not yet wired into bootstrap.** Local astronomy computation exists in the schema but the fixture-driven bootstrap currently leaves `now.moon` empty. Trivial fix; deferred to keep this commit focused.
3. **Open-Meteo model_run_iso is approximated.** The API does not return the actual model run timestamp; we stamp it as `now - 6h` because that is the documented maximum cycle lag for the underlying NWP. Real production needs to fetch `/v1/models-updates` and stamp the actual run.
4. **NDBC 44084 wind/pressure gap.** Confirmed in the 2026-08-18 20:00 ET snapshot: 44084 reports waves only, not wind/pressure. The briefing uses 44009 (Delaware Bay) for wind/pressure, which is 11 nm from Ocean City. The reconciler correctly downgrades confidence when these two sources disagree.
5. **No paid-feed evaluation yet.** Stormglass / Spire / PredictWind comparison is deferred until the dev MVP ships and we can quantify the actual gap.
6. **Single-fixture load.** `bootstrap.js` only mounts `ocean_city_normal`. The `degraded` and `mismatch` fixtures exist for tests but are not exposed in the UI. Dev follow-up: add a fixture-switcher behind a query param (`?fixture=degraded`) for internal review.
